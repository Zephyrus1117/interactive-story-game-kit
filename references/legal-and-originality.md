# Legal And Originality

Use this reference before reusing any third-party skill, launcher, README, sample story, UI copy, visual design, or generated asset.

## Clean-Room Default

Prefer a clean implementation:

- write new skill instructions
- write new examples
- write new UI labels and onboarding copy
- write new default stories
- use a distinct visual direction
- avoid visible third-party brand lines, usernames, slogans, contact details, or project names

Do not copy distinctive prose, sample scenes, UI phrasing, variable names, or branded credits from another project unless the user explicitly asks and the license allows it.

## MIT Or Permissive Source Use

When a permissive license allows reuse:

- keep the license notice when distributing copied or modified code
- identify which files are derived
- remove visible brand marks only if the license permits removal and attribution remains in the license notice
- do not imply the original author endorses the new project

If the goal is to avoid brand/copyright confusion, do not derive the public-facing launcher from the original. Build or use the clean template in `assets/themeable-launcher/index.html`.

## AI-Generated Stories

For new examples:

- use original characters, places, institutions, conflicts, and titles
- avoid close analogues of known works unless the user requests parody, critique, or licensed adaptation
- do not use celebrity likeness, real private people, or trademark-heavy settings as defaults
- document when a story is a prototype rather than a finished game

## Branding Checklist

Search all delivered files for:

- third-party usernames or handles
- `Powered by` strings
- original project names
- contact emails from source projects
- copied README prose
- license text without clear context
- default examples from source projects

The validator also scans common brand-residue strings, but manual review is still required.
